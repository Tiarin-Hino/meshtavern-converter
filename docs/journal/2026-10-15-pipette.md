## What we did

The painting view can now tell the colour under a point of the mini, so a painter can pick a colour already on it and go on painting with it. There are two ways to pick: as shown, the colour exactly as it looks on screen with the light and shading on it, and as painted, the paint's own colour, the same one the brush laid. As shown is the default. The table draws the pipette button; the team's Paint tool under `?dev` has one (Pick a colour, with the mode beside it) to try it.

## Why

After testing the hobby brushes (#128, PR #132) the PM asked for a pipette, to carry on or touch up an area in the colour it already has. The issue left three questions open; the PM answered them on #135 on 2026-10-13: offer both modes ("if I copy dark blue, I want dark blue" for as shown; as painted for colouring shaded parts with the same paint), as shown by default. That also settles the other two questions: as shown, a thin wash or a bare spot gives what the eye sees over the primer; as painted, a texel gives its paint's colour whatever its alpha, and a bare texel gives nothing.

## How

- **One method on the view, not a tool.** `colourAt(x, y, mode?)` returns `#rrggbb` or null. Picking is not one of the view's tools: the consumer's button waits for the next tap, asks `colourAt` and passes the answer to `setColour`. That keeps the view's pointer rules (§9 of the design note) as they were, and a table can put the pipette wherever its palette is. The `?dev` tool does exactly that: a capturing `pointerdown` listener on the view's host element, which runs before the view's own listeners on its canvas, so a pick never starts a stroke or an orbit.
- **As shown reads the screen inside the frame.** The view's renderer does not keep its drawing buffer (`preserveDrawingBuffer` off, as it should be for speed), so a read after the frame gives nothing useful. `PaintScene.pixelAt` queues a read that the render loop runs right after `render`, in the same frame: one `readPixels` of one pixel of the default framebuffer, which WebGL resolves from the antialiased buffer. The point in CSS pixels becomes a drawing-buffer pixel by the buffer's size (the pixel ratio is capped at 2) and is flipped, since WebGL counts rows from the bottom. The canvas holds sRGB bytes already, so they are the answer.
- **As painted reads one texel.** `texelAt` already finds the texel under a point; `PaintPasses.readTexel` reads that one texel of the committed paint (`readRenderTargetPixelsAsync`, 1×1). The paint is stored as sRGB bytes with straight alpha, so the colour comes back as the hex it was painted with.
- **Off the mini** (the backdrop, the grid) both modes give null: the ray must hit the mini first. A stroke still on the canvas is committed first, as every other method of the view does.
- **Words.** `PAINT_COPY.pick`: the button, the two modes, a hint and what to say when there is nothing to pick. Proposals the PM may change.

## Problems and how we solved them

- **Problem.** The first test's bare point gave null as shown, though `texelAt` found the mini there. **Cause:** the point, on the figure's leg, lay below the canvas at the test's camera; `texelAt` casts the ray whatever the canvas's size, but there is no pixel to read off the canvas. **Fix:** the test picks a bare point beside the stroke, on screen. `pixelAt` returns null for a point off the canvas, which is the right answer.
- **Problem.** The e2e run would not start: the server's build failed, then the browser was missing. **Cause:** a type error in the new test, and Playwright's bump in #153 needs a newer Chromium build. **Fix:** the type, and `npx playwright install chromium` once on the development PC.

## Numbers

On the generated figure, the chest painted with `#b03030` at full opacity, seen from the front (`setCamera(0, 5, 1.6)`), development PC, headless Chromium (e2e):

| Point          | As painted | As shown  |
| -------------- | ---------- | --------- |
| Painted chest  | `#b03030`  | `#8b4b4b` |
| Bare, below it | null       | `#83888f` |
| Off the mini   | null       | null      |
| The bare back  | null       | —         |

The paint's bytes come back exactly. As shown, the same red is darker and greyer under the table's light and the look: what the person sees.
