## What we did

The end-to-end tests ran in one CI job that had grown to 37 minutes, 34 of them the tests. They now run in three jobs at once (shards), each on its own runner with two browsers, next to a fourth job that runs `npm run check`; a last job joins the shards' results into the one HTML report the run always had. The painting engine's spec, one file of 45 tests, is four files with their helpers in a module of their own. No test changed what it checks.

## Why

Main's run of #167 (2026-10-21): the check 3 minutes, the e2e step 33 minutes 49 seconds. The report shows why: the runner's two Playwright workers each take a file at a time, and `painting.spec.ts` alone held 1,079 s of tests. It started on the third worker index at 935 s and ran until 2,018 s; the other worker finished its last file at 996 s and stood idle for the remaining 17 minutes. Playwright keeps a file's tests on one worker unless the file says otherwise, and the file could not: its tests share one converted figure per worker (a worker fixture), because thirteen conversions in software rendering had loaded the runner enough to time out another file's test.

## How

- **The split.** `e2e/painting-helpers.ts` holds what the tests share: `convert`, the figure fixture (`test` with `figure` and `figurePage`) and every helper (`brushOver`, `chestPath`, `maskTheChest`, `openWithTheArmApart`, …). The tests went, unchanged and in their order, into `painting.spec.ts` (open, strokes, input, undo, fill, eraser, lift: 14 tests, 308 s on CI), `painting-brushes.spec.ts` (hobby brushes, pipette, subscribers, swatches: 12, 317 s), `painting-mask-groups.spec.ts` (mask, groups, pulled apart: 14, 287 s) and `painting-own.spec.ts` (the five tests with a mini of their own: 166 s). The split was made by a script and checked line by line: every line of the old file is in one of the five, only the imports and the headers are new.
- **The tests with a mini of their own** came first in the old file, because once the shared figure's page exists it keeps drawing beside them. In their own file they use Playwright's own `test`, without the fixture: a worker fixture is part of what Playwright groups workers by, so they never share a worker with a figure page.
- **Three shards.** `ci.yml` has a `scope` job (the docs-only rule, unchanged), `check`, `e2e` as a matrix of `--shard=1/3` to `3/3` with the blob reporter, `report` (`playwright merge-reports` into `playwright-report`, and the shards' differing reference pictures into the one `reference-screens-actual` artifact that `npm run shots:take` reads), and `ci`, the required check, green when `check` and every shard passed or the shards were skipped for a docs-only PR. The repository is public, so the extra runners cost no minutes.
- **How Playwright shards** (1.64, `filterForShard`): by test count, in file order, whole files. So with the split, shard 1 is the page, questions, paint file and painter files plus `painting-own` (52 tests), shard 2 smoke, reference screens, promise and the rest (53), shard 3 the three figure files (40). From the durations of main's run that is about 600, 450 and 460 s of tests for two workers each. A spec file over about six minutes would again set a floor under its shard.

## Dead ends

- **`fullyParallel` or `mode: 'parallel'` for the painting file**, instead of splitting it: each test would land on any worker, every worker would convert the figure, and a figure page would draw beside the tests with a mini of their own. The split keeps the order and the sharing the old file had.
- **Shard weights** (`PWTEST_SHARD_WEIGHTS`): whole files make the shards coarse; no weighting of three beat the even split by more than a few percent, and weights go stale as tests are added.
- **More workers per runner:** the runners have four cores, software WebGL takes them, and #156 and #184 were timeouts of tests loaded by a neighbour.

## Numbers

- Before: main's run for #167 on CI, 37 minutes in all, the e2e step 33:49; 145 tests, 2,995 s of test time.
- After: _to be filled from this PR's CI run._ Expected from the same durations: about 10 minutes of tests per shard plus about 2 of set-up (npm ci, Chromium, the build), the run about 13 minutes in all.

## Still open

- The shards' balance follows the test count, not the time; a new slow spec file goes where its name sorts.
- The page is built twice per run (in `check` and in each shard's web server); about 30 s each, left as it is.

## Story angle

Seventeen idle minutes per run hid behind one file. "The slowest test file sets the floor": splitting a suite for parallel runners.
